# blackhole-compressor · 亚稳态黑洞遏制场自动化(深度改良版)

控制 16 台 `multimachine.blackholecompressor` 的批量压缩:投黑洞种子 → 时空红石信号维持稳定度 → 网络清空后投黑洞坍缩器关洞 → 反馈确认全部关闭才断时空信号。

- 机制与结构:[GTNH 中文维基·指南:亚稳态黑洞遏制场自动化](https://gtnh.huijiwiki.com/wiki/%E4%BA%9A%E7%A8%B3%E6%80%81%E9%BB%91%E6%B4%9E%E9%81%8F%E5%88%B6%E5%9C%BA%E8%87%AA%E5%8A%A8%E7%BB%B4%E6%8C%81%E6%95%99%E7%A8%8B)(维基页内嵌脚本,**无上游仓库**;页内代码见 `wiki/`)。
- 本脚本在其基础上深度改良,差异见下。

## 相对 wiki 版的改动

- **maxTime 275s**(wiki 300s):黑洞稳定时间过长即重启。
- **黑洞反馈确认**(wiki 版没有):黑洞多功能仓(静态模式)信号并联接入红石 I/O 的非输出面,`useFeedback=true` 时以"全部反馈面归零 + 无机器在跑配方持续 3s"判定全部关闭,才切断时空信号;未检测到反馈自动退回 wiki 的旧等待逻辑。
- **补投波次**:有配方在跑时按批量补投坍缩器,避免已关洞的空闲机器把坍缩器白吃;干净模式只补 1 个。
- **启动恢复**:启动时若仍有残留黑洞,先保持时空信号把它们关掉再开新洞,避免断时空导致失稳吞材料。
- **异常退出保护**:pcall 失败且仍有黑洞未关时保持时空信号、冻结稳定度,报错等待人工处理。
- 时空信号输出面 `sides.south`(wiki 版为 north,按实际布线改)。

## 接线要求

- 转运器 south 进料 / down 出到共享输入总线;槽 1 = 黑洞种子,槽 2 = 黑洞坍缩器(数量不足时屏幕报错并等待补货)。
- 红石 I/O:输出面接时空稳定度信号;输入面并接 16 台黑洞多功能仓的静态模式反馈(反馈面不能与输出面共用)。
- 屏幕显示状态机:[空闲]→[运行中]→[关闭中],反馈异常转[警告]。

**红线:黑洞未全部关闭时绝不能断时空信号,否则失稳吞材料。**
